# 自动清洗刮板回零与刮墨流程优化记录（2026-06-02）

## 1. 背景与目标

现场反馈自动清洗流程中刮板回零耗时偏大，且对清洗节拍有明显影响。  
本次目标：

- 缩短单次自动清洗时长；
- 保留必要的物理回零，避免刮墨角度累计偏移；
- 保证手动清洗的可靠性（每次手动清洗仍进行物理回零）；
- 修复并澄清刮板“回等待位”与“物理回零位”的语义差异。


## 2. 关键问题复盘

### 2.1 刮前回零重复执行

原短流程在“升刮板到 135°”前调用 `HomeInkScraperAxis(...)`，其内部可能触发 `SetBackSpreaderAxis(...)`。  
但 `TrapMoveSpreaderAxis(...)` 本身会执行 `GT_ZeroPos + GT_SetEncPos(0)` 后再按目标角运动，导致刮前物理回零与后续 Trap 坐标清零存在重复。

### 2.2 刮后“回等待位”不等于“回物理零位”

原逻辑曾使用 `TrapMoveSpreaderAxisRelative(..., +Δ)` 进行收回。  
该动作只是回到 Trap 的相对坐标参考点，并不等价于 `SetBackSpreaderAxis` 基于 Home 传感器建立的物理零位。

### 2.3 手动清洗时长偏长的主要来源

日志显示手动清洗入口会在流程末尾执行强制物理回零（策略要求），该段通常增加约 2~4 秒（取决于速度与机构状态）。


## 3. 本次修改内容

修改文件：

- `1-3DP主控界面(人机交互模块)/手动操作界面.cs`
- `1-3DP主控界面(人机交互模块)/主界面.cs`（修复一次编译语法问题）

### 3.1 新增自动清洗回零周期计数（自动入口）

新增字段：

- `private static int s_nAutoCleanRunCounter = 0;`
- `private const int AutoCleanPhysicalHomeEveryNRuns = 8;`

策略函数 `ResolveForcePhysicalHomeForAutoClean()`：

- 手动入口（`m_bManualAutoCleanEntry == true`）：本轮结束强制物理回零；
- 自动入口：`runCounter++` 后按 `% 8 == 0` 判断是否在本轮结束执行物理回零。

> 说明：此计数不是 `for(ci...)` 清洗遍数计数，而是 `AutoCleanThread2` 被调用的会话计数。

### 3.2 调整短流程刮板动作顺序（去掉刮前物理回零）

短流程中原先“刮前 `HomeInkScraperAxis`”已移除，改为：

1. 直接 `TrapMoveSpreaderAxis(4, axisVel, -relativeCleanAngleDeg)` 升到 135°；
2. 墨车回刮至 750；
3. `TrapMoveSpreaderAxis(4, axisVel, 0)` 回 Trap 等待位。

这样可避免刮前重复寻零。

### 3.3 保留物理回零但后移到流程末尾

短流程循环结束后：

- 若策略判定本轮需要物理回零（手动每次/自动每8次），执行  
  `HomeInkScraperAxis(axisVel, "AutoCleanThread2_EndPhysicalHome", false, true)`。

该策略兼顾节拍与漂移控制。

### 3.4 修复一次编译错误

`主界面.cs` 中 `else if (Command == 6)` 曾被误拼接到注释行尾导致语法错误（CS1002/CS1525 等）。  
已将注释与 `else if` 拆分为独立行并修复。


## 4. 当前生效工艺行为（短流程）

短流程路径（当前 `return` 生效分支）：

1. 墨车到压墨位（X=750,Y=245）；
2. 压墨 2 秒；
3. 墨车到新清洗位（请求 860，受保护上限后为 855）；
4. 刮板 Trap 转至 135°（基于 `relativeCleanAngleDeg = 135 - home`）；
5. 墨车以 20 mm/s 回刮到 750；
6. 刮板 Trap 回等待位 0°；
7. 本轮若命中策略则执行流程末尾物理回零。


## 5. 参数与可调点

### 5.1 回零周期

- 常量：`AutoCleanPhysicalHomeEveryNRuns = 8`
- 如需现场调整为 5/10 次，可直接改该常量，后续可配置化（JSON/UI）。

### 5.2 刮墨角度

当前短流程角度为局部常量：

- `const double scraperCleanAngleDeg = 135.0;`

如需改角度可修改该值（后续可改为读取配置）。


## 6. 日志验证要点

### 6.1 判断刮前是否还有物理寻零

若在“准备升刮板到 135°”后不再出现：

- `开启刮墨轴回零校准：AutoCleanThread2_Cycle*_BeforeScrape`
- `SetBackSpreaderAxis ... BeforeScrape`

则说明刮前物理寻零已移除（符合本次改造）。

### 6.2 判断是否命中末尾物理回零

查看是否出现：

- `开启刮墨轴回零校准：AutoCleanThread2_EndPhysicalHome`
- `自动清洗：本轮结束已执行刮板物理寻零（手动每次 / 自动每8次）`

手动入口应每次出现；自动入口应每 8 次出现一次。


## 7. 已知边界与建议

- `s_nAutoCleanRunCounter` 为进程内静态计数，程序重启后归零；
- 自动入口计数按“调用次数”而非层号，不与 `m_nCleanTimes`（单次清洗内遍数）直接绑定；
- 若后续要实现“按层号周期回零”或“可视化展示当前计数”，建议将周期与计数状态配置化并在 UI 展示。


## 8. 结论

本次改造实现了：

- 去除刮前重复物理寻零；
- 保留必要物理回零并后移到流程末尾；
- 手动清洗每次回零、自动清洗按 8 次周期回零；
- 修复相关编译问题并完成日志可观测性增强。

整体上在保证角度可靠性的前提下减少了清洗流程中的冗余耗时。
